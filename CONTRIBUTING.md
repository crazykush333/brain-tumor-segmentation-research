# Contributing

This is a pre-registered study. Contributions are welcome **only** where they keep the frozen design intact.

## Non-negotiable rules

1. **The frozen protocol is immutable.** `docs/research/FINAL_RESEARCH_PROTOCOL_v1.0.md` (tag `protocol-v1.0`) is never edited, renamed or re-versioned. A design change requires a logged amendment in protocol §25, approved by the owner. The regression tests and `brats-uncertainty verify-protocol` fail if the file's SHA-256 changes.
2. **No data in the repository.** Never commit MRI scans, NIfTI/DICOM files, label volumes, arrays derived from patient data, licensed metadata (crosswalks, collection spreadsheets), checkpoints, credentials or API keys. `make check` runs `brats-uncertainty check-repo`.
3. **No fabricated numbers.** Never type a hash, count, T_screen value, Dice, AURC, CI, p-value or runtime by hand. Numbers enter the repository only as provenance-stamped artifacts written by the code from real inputs.
4. **Synthetic data stays synthetic.** Test fixtures are generated in memory, carry `SYN-` IDs and are never described as BraTS data or used as results.
5. **Gates are closed with evidence.** A gate in `docs/project_status.yaml` may be set to `CLOSED` only with an existing evidence file and a date, and only by the owner or on the owner's instruction.

## Workflow

```bash
pip install -e ".[dev]"
make check              # lint, format check, types, tests, repository scan, website-data sync
make site-data          # after editing docs/project_status.yaml or configs
```

- Branch from `main`. Keep commits focused and write messages in the imperative.
- Every change to analysis code needs tests (synthetic fixtures only).
- Implementation choices the protocol leaves open must be documented in `docs/reproducibility/REPRODUCIBILITY.md` (§ "Implementation choices") and flagged for owner confirmation.
- Website text must stay data-driven: status and numbers come from `website/data/*.json`, generated by `brats-uncertainty export-site-data`.

## Reporting problems

Open an issue describing the problem. For security or data-exposure problems, follow [SECURITY.md](SECURITY.md) instead.
