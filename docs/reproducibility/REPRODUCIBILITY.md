# Reproducibility

**Status:** the software is implemented and tested on synthetic inputs only. No study data, splits, models or results exist.

## 1. Sources of truth

| What | Where | Guarded by |
|---|---|---|
| Scientific design | `docs/research/FINAL_RESEARCH_PROTOCOL_v1.0.md` (tag `protocol-v1.0`) | SHA-256 over LF-normalized text (`704c0b49…d9811`), checked by `load_protocol()` on every use and by the regression tests against the tagged git blob |
| Design parameters for code | `configs/protocol/protocol_v1.0.yaml` | regression tests assert each value appears in the protocol text and matches the package constants |
| Project / gate state | `docs/project_status.yaml` | schema validation: CLOSED needs evidence; B gates close in order |
| Website data | `website/data/*.json` | generated by `brats-uncertainty export-site-data`; CI fails if it is stale |

## 2. Recorded per run (protocol §24)

Experiment ID; git commit; config SHA-256; protocol SHA-256; nnU-Net version and plans file; split file hashes; crosswalk and UCSF-PDGM metadata SHA-256; §6.2 screen output; GPU, CUDA, PyTorch and Python versions (`utils/environment.py`); wall-clock time and peak memory; per-unit metric CSVs. Result artifacts are written only through `results/artifacts.write_artifact`, which refuses incomplete provenance.

## 4. Implementation choices the protocol leaves open

These are software decisions, not design changes. Each is fixed in code, covered by tests, and **flagged for owner confirmation before `eval-v1` (gate C6)**, or before the gate named in the table. If the owner prefers a different choice, it is changed before that gate; after it, it can change only through a logged §25 entry.
