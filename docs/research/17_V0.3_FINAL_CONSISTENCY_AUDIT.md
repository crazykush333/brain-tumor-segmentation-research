## 1. Executive verdict

**v0.3 is internally coherent for H-W's mechanics, but it is not ready for freeze.** Four owner decisions and one lifecycle restructuring are needed first. No protocol text was changed in this audit.

1. **C5 "Full" is inside the primary H-W average.** Full is not a missing-sequence condition, so this is a conceptual mismatch with §1. **OWNER SCIENTIFIC DECISION REQUIRED** (§2.1).
2. **H4 is stated but not tested.** §2.2 states "arm A is weaker than arm B", but family F5 only tests arm A's own ΔAURC_c < 0. **OWNER REVIEW REQUIRED** (§2.2).
3. **The §19 "confident failure" rule does not match τ_0.80.** "U1 above the validation 80th percentile" is **not** the same set as "U1 ≥ τ_0.80", even without ties. τ_0.80 accepts about 80% of units; the 80th percentile selects about the top 20%. Replacing one with the other would change the definition of a confident failure, so **it was not applied as an editorial fix**. **OWNER DECISION REQUIRED** (§2.3).
4. **The pre-freeze checklist mixes true freeze blockers with post-freeze execution gates.** The freeze rule then becomes logically unsatisfiable. For example, the crosswalk hash "at split time" cannot exist before v1.0, because splits are forbidden before v1.0 (§3).
5. **T_screen remains unresolved.** A candidate rule (minimum WT-Dice of the verified positive pairs) is analysed but not adopted. **OWNER DECISION REQUIRED** (§4).
6. **Literature items.** LNCS 15354 (BraTS 2024 proceedings) could not be located in the indexes accessible to this audit; **UNVERIFIED** (§5). PNDC: **FULL TEXT STILL UNVERIFIED** (§6).

**Minor terminology notes** (reported earlier, still open): §3 "Units within condition c = patients" (a locked section), §13 supporting Wilcoxon "per-patient", §19/§24 "(patient, condition) units". Under A1 these should read case / patient group. They do not affect the H-W bootstrap.

### 2.1 Full condition in H-W — OWNER SCIENTIFIC DECISION REQUIRED

| Aspect | **Option A**: average over all 5 C5 conditions (current) | **Option B**: average over the 4 single-missing conditions; Full becomes a pre-specified supporting control |
|---|---|---|
| What H-W tests | Whether U1 ranks ET failures better than chance within each input condition, on average **including complete inputs** | Whether U1 ranks ET failures better than chance within each **missing-sequence** condition, on average |
| Is I conceptually valid? | Within Full, I is constant (as in every condition), so ΔAURC_Full = U1 vs chance on complete inputs. It is mathematically valid, but "beyond missingness identity" is vacuous for Full, where nothing is missing. | Valid and meaningful in all four included conditions |
| Can Full dilute or drive the result? | **Yes.** Full carries 1/5 of the weight. Complete-input ensemble discrimination is expected from prior literature and may have a different risk spread, so it can **drive** a positive mean or **mask** weak discrimination in the missing conditions. | No. Full is reported separately as a reference: missing-condition components are compared against it descriptively. |
| Alignment with §1 | Partial | **Tighter**: §1 asks "within a given missing-sequence condition" |
| Other effects | None | F1 would then contain 4 missing-condition tests (Full becomes descriptive), or keep 5 with Full labelled as reference. The novelty statement matches the endpoint more closely. C5 itself is unchanged (still inferred and reported). |
| Amendment size | — | **Substantive.** It changes the primary endpoint definition (§2.1, §3, §13) and F1. It is permissible pre-freeze because no data have been seen, but it needs owner authorization, a logged amendment and a new version (v0.4). |

The audit does not choose. On scientific alignment Option B is the stronger match to the stated question, but Option A keeps the approved endpoint unchanged.

### 2.2 H4 — OWNER REVIEW REQUIRED

- **§2.2 H4:** "For arm A under missing inputs, within-condition discrimination is **weaker than for arm B**."
- **§14 F5:** "arm A ΔAURC_c for the 4 missing conditions (4 tests); claimed if Holm-adjusted p < 0.05 and estimate < 0." That tests *arm A better than chance*, **not A vs B**.

So H4 as worded is **not statistically tested** [VERIFIED by reading §2.2 and §14].

**Preferred clean fix** (no new family): re-word H4 as a **supporting descriptive comparison**:

> "Arm A within-condition ΔAURC_c (c ≠ Full) is reported as F5 (arm A vs chance, Holm within F5). The comparison with arm B is descriptive (paired patient-group bootstrap CI of the difference); no confirmatory B-vs-A test is made."

This changes hypothesis wording, not any test. It still needs owner approval because it edits §2.2.

### 2.3 Failure-analysis threshold (§19) — OWNER DECISION REQUIRED (not applied)

- **§19:** "Confident failure: U1 above the validation 80th percentile and ET Dice < 0.5."
- **§4 S7:** τ_0.80 = the largest observed U1 with coverage(validation, U1 ≥ τ_0.80) ≥ 0.80, which accepts the **top ≈ 80%** most-confident units.
- The validation 80th percentile of U1 marks the **top ≈ 20%**. These sets differ **even without ties**. The instruction's premise (a tie issue) does not hold, so replacing the wording is **not** an editorial consistency fix.

Two defensible deterministic options, both using the §4 S7 rule:

- **(i) "U1 ≥ τ_0.80".** "Confident failures" become failures **accepted at the primary operating point**, i.e. silent failures under the deployment rule. This aligns failure analysis with S7, but broadens the set considerably.
- **(ii) "U1 ≥ τ_0.20"**, with τ_0.20 defined by the same ≥ rule at q = 0.20. This preserves the original intent (the top-20% most confident), made deterministic and tie-safe.

§19 is descriptive failure analysis, not an endpoint, so either choice is low-risk. Choosing between them is a scientific definition choice. **No change was made; the v0.3 changelog was not updated for it.**

## 4. T_screen analysis — OWNER DECISION REQUIRED

**Repository evidence.** A search of all project documents (2026-09-28) found **no** documented WT-Dice threshold for same-patient detection. The only positive evidence is the two verified pairs, A (00626/00758, 7 days apart) and B (00639/00557, 3 days apart). Their WT-label Dice values are **not known**, because computing them needs the label files (a post-freeze data gate).

**Candidate rule:** T_screen = the minimum WT-label Dice observed among the two verified same-patient pairs.

| Aspect | Assessment |
|---|---|
| Strengths | Data-anchored, not arbitrary. Deterministic. Can be frozen as a *rule* before any screening output is seen. Uses only ground-truth labels and TCIA metadata, i.e. permitted pre-split information, with no model output. |
| Guarantees | By construction, both known positive pairs are flagged (they are at or above the threshold). |
| Does not guarantee | Detection of same-patient pairs with **longer intervals** or post-treatment change. Both anchors are short-interval (3 and 7 days) pre-operative UCSF scans, so their Dice is plausibly high [INFERENCE] and the threshold may be **too strict** for other follow-ups (e.g. the 175-day UCSF pair, whose second member is not in BraTS 2021). No sensitivity estimate is possible with n = 2 positives, and there is no specificity estimate at all. |
| Permitted information? | Yes, provided it is computed at the data gate (B4) before the split and without model outputs. |
| Freeze before screening? | Yes. The rule (not the number) must be frozen before the pairwise matrix is inspected, to avoid threshold-shopping. |
| Better rules? | (a) **Anchor plus rank-based review budget:** flag all pairs ≥ the anchor minimum, **plus** each case's single most-similar partner if it exceeds a pre-set lower floor. This raises sensitivity at bounded review cost, but the floor is again a choice. (b) **Add permitted metadata:** the crosswalk carries study dates for 637 training rows and site IDs. Restricting to same-site pairs cuts false positives, since same-patient follow-ups across sites are implausible [INFERENCE]. (c) **Conservative handling:** unresolved pairs are grouped. Over-grouping costs little statistical efficiency, whereas leakage harms validity. |

The audit's analysis favours **anchor-minimum + same-site restriction + conservative grouping of unresolved pairs**. This is recorded for the owner and **not adopted**.

**Minimum content of the manual-review procedure (to be pre-specified by the owner):**

- **Reviewer:** named reviewer(s). The owner, plus a second reviewer for disagreements if available. Reviewers are not blinded (there is nothing to blind to) but must not see any model output.
- **Material inspected:** co-registered T1, T1c, T2 and FLAIR plus WT labels for both cases side by side (same slices); crosswalk metadata (site, collection, study date if present). No predictions, no metrics beyond the WT-Dice that triggered the flag.
- **Decision categories:** SAME PATIENT / DIFFERENT PATIENT / UNRESOLVED.
- **Decision rule:** SAME if non-tumour anatomy (ventricular configuration, sulcal pattern, skull-strip outline) and lesion location/morphology are concordant beyond what distinct patients would plausibly share. Otherwise DIFFERENT. UNRESOLVED if image quality prevents a judgement.
- **Reason recording:** a free-text reason and a timestamp per pair in a committed CSV (IDs only).
- **Unresolved pairs:** grouped (conservative).
- **Transitive grouping:** the union-find closure over SAME and UNRESOLVED links, plus groups A/B and any shared TCIA IDs; the final group list is frozen before the split.
